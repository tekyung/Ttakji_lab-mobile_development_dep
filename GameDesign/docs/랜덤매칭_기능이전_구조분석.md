## 2. GameMatchingManager 프리팹 점검 결과

> 프리팹 경로: `Assets/Firebase/prefabs/GameMatchingManager.prefab`

### 2-1. 프리팹 컴포넌트 구성

| 컴포넌트 | 매칭에 필요? | 상태 |
|---------|-----------|------|
| `session_manage` | ✅ 필요 | ✅ 포함됨 |
| `firebase_network` | ✅ 필요 | ✅ 포함됨 |
| `EventService` | ❌ 불필요 | ⚠️ 포함됨 (게임플레이 전용, 제거 권장) |

### 2-2. 참조 연결 상태

| 프로퍼티 | 대상 | 상태 |
|---------|------|------|
| `session_manage.networkService` | `firebase_network` | ✅ 연결됨 |
| `session_manage.uiManager` | `session_ui` | ✅ **null-safe 처리 완료** — 미할당이어도 정상 동작 |
| `session_manage.session_time_limit` | 50 (초) | ✅ 설정됨 |
| `EventService.networkService` | `firebase_network` | ✅ 연결됨 (불필요 컴포넌트) |

### 2-3. 해결된 항목

| 항목 | 설명 | 해결 방법 |
|------|------|---------|
| `session_ui` 의존성 | 프리팹에 없고 MainMenu에도 없음 | ✅ `session_manage`의 모든 `uiManager` 호출을 null-safe로 변경 |
| ID 획득 | MainMenu에 ID 입력 UI 없음 | ✅ `GetOrGenerateID()`로 0~999999 랜덤 ID 자동 생성 |
| 상태 표시 | `session_ui.UpdateStatus()` 사용 불가 | ✅ `onStatusUpdate` 콜백으로 `RandomMatchUI.timerText`에 표시 |
| 매칭 성공 알림 | 외부 UI에 알림 수단 없음 | ✅ `onMatchedAndReady` 콜백 추가 |
| 버튼 연결 | `BtnRandomMatch` → `RandomMatchUI.StartRandomMatch()` | ✅ 유지. `StartRandomMatch()` 내부에서 `session_manage.OnClickRandomMatch()` 호출 |

### 2-4. `session_manage`의 `session_ui` 의존성 해소 방식

| 기존 호출 | 변경 후 | 동작 |
|---------|--------|------|
| `uiManager.GetID()` | `GetOrGenerateID()` | uiManager 있으면 InputField 사용, 없으면 랜덤 ID 생성 |
| `uiManager.UpdateStatus(msg)` | `NotifyStatus(msg)` | `uiManager?.UpdateStatus()` + `onStatusUpdate?.Invoke()` 동시 호출 |
| `uiManager.ToggleUI(bool)` | `uiManager?.ToggleUI(bool)` | null-safe (MainMenu에서는 무시됨) |
| `uiManager.ToggleHost(bool)` | `uiManager?.ToggleHost(bool)` | null-safe (MainMenu에서는 무시됨) |
| `uiManager.DestroySessionTimer(float)` | `uiManager?.DestroySessionTimer(float)` | null-safe (MainMenu에서는 무시됨) |

## 3. 기능 흐름 비교

### 2-1. Server UI — `OnClickRandomMatch()` (실제 매칭)

```
사용자 클릭
  │
  ▼
① myID = uiManager.GetID()  ← 입력필드에서 ID 획득
   ├─ 비어있으면 → "Enter ID" 표시 후 return
  │
  ▼
② uiManager.UpdateStatus("Searching...")
   uiManager.ToggleUI(false)  ← 모든 버튼 비활성화
  │
  ▼
③ publicRooms = await networkService.GetPublicSession()
   │  └─ Firebase에서 sessions 노드 조회
   │     state == "WAITING" && secret == "PUBLIC" 인 세션 코드 목록 반환
  │
  ├─ publicRooms.Count > 0 인 경우 ─────────────┐
  │   ▼                                          │
  │  랜덤 인덱스 선택                              │
  │  await JoinSessionProcess(targetRoom)         │
  │   ├─ networkService.JoinSession() 호출        │
  │   ├─ guest 필드에 myID 기록                    │
  │   ├─ ListenForGameStart() 등록                │
  │   └─ ListenForSessionExit() 등록              │
  │                                               │
  └─ publicRooms.Count == 0 인 경우 ──────────────┘
     ▼
    await CreateSession(isPublic: true)
     ├─ 4자리 랜덤 세션 코드 생성
     ├─ session_data 객체 생성 (secret = "PUBLIC")
     ├─ networkService.CreateSession() 호출
     ├─ ListenForGuest() 등록
     └─ AutoDestroySession 타이머 시작 (50초)
```

### 2-2. MainMenu — `StartRandomMatch()` (더미 매칭)

```
사용자 클릭 BtnRandomMatch
  │
  ├─ RandomMatchUI.StartRandomMatch() 호출
  │   ├─ 타이머 초기화 (timer = 0)
  │   ├─ PopupRandomMatching 활성화 (타이머 표시)
  │   └─ Update()에서 timer 증가
  │       └─ matchSuccessTime(20초) 도달 시 → MatchSuccess()
  │           ├─ PopupRandomMatched 활성화
  │           └─ 1초 후 SceneManager.LoadScene("TestGameScene")
  │
  └─ PopupMatchMode.SetActive(false)  ← 매칭모드 선택 팝업 숨김
```

> **핵심 차이**: MainMenu의 `RandomMatchUI`는 Firebase 통신 없이 타이머만으로 매칭을 시뮬레이션한다. 실제 상대방과 매칭되지 않는다.

## 6. 구현 결정 사항

### 6-1. ID 획득 방식
- **결정**: `Random.Range(0, 1000000)` 으로 0~999999 사이 랜덤 숫자 ID 자동 생성
- `session_manage.GetOrGenerateID()`: `uiManager`가 있으면 InputField 사용, 없으면 랜덤 생성
- 추후 닉네임/계정 시스템 도입 시 이 부분만 교체하면 됨

### 6-2. Firebase 초기화
- `session_manage.Start()`에서 `networkService.Initialize()` 자동 호출
- MainMenu 씬 로드 시점에 초기화되며, 결과는 `NotifyStatus()`를 통해 전달
- 추후 씬 전환 시 중복 초기화 방지 (Singleton 또는 DontDestroyOnLoad) 고려 필요

### 6-3. 매칭 후 씬 전환
- `session_manage.HandleGameStarted()`에서 `GameData` 설정 후 `TestServerConnect` 씬 로드
- `RandomMatchUI`에서는 씬 전환을 직접 하지 않음 (기존 `CoGoToBattleScene` 제거됨)

### 6-4. 매칭 대기 UI
- `timerText`가 `session_manage.onStatusUpdate` 콜백을 통해 실시간 상태 메시지 표시
- 표시 예: "Searching..." → "Room Created: 1234" → "Player123 Joined!" → "3..." → "Game Start!"

### 6-5. 매칭 취소
- `CancelRandomMatch()`에서 `matchManager.OnClickExitSession()` 호출
- Firebase 세션 삭제 처리 포함 (호스트: 세션 삭제 / 게스트: guest 필드 비우기)

### 6-6. 세션 타임아웃
- `session_manage.AutoDestroySession()` 코루틴이 null-safe하게 동작
- 50초 후 자동 세션 삭제 (`uiManager?.DestroySessionTimer()` — MainMenu에서는 무시됨)

| **타이머 vs 상태메시지 경쟁** | **높음** | ⚠️ 수정 필요 | `Update()`가 매 프레임 `timerText`를 덮어써서 상태 메시지가 보이지 않음 |
| 이벤트 `=` 대입 방식 | 낮음 | 💡 개선 권장 | 현재 구독자 1명이라 무해하지만, 확장 시 덮어쓰기 위험 |
| `CancelRandomMatch` 이벤트 해제 순서 | 낮음 | 💡 개선 권장 | "session exit" 피드백이 UI에 미표시 |
| Firebase 중복 초기화 | 낮음 | 💡 개선 권장 | 기능상 안전하지만 불필요한 호출 발생 |
| Inspector 직렬화 값 유실 | 무해 | ✅ 영향 없음 | 제거된 필드(`matchSuccessTime`, `nextSceneName`)의 기존 값만 유실 |

### 9-2. 상세 분석

#### (1) `server ui` 씬 — 영향 없음 ✅

`session_manage.cs`의 모든 변경은 기존 `server ui` 씬의 동작에 영향을 주지 않습니다.

- `uiManager?.` null-safe 호출: `server ui`에서는 `uiManager`가 항상 할당되어 있으므로 기존과 동일
- `NotifyStatus()`가 `onStatusUpdate?.Invoke(msg)`도 호출하지만, 아무도 구독하지 않으므로 무시됨
- `onMatchedAndReady?.Invoke()`도 구독자 없으므로 무시됨
- `GetOrGenerateID()`는 `uiManager != null`이면 기존처럼 `uiManager.GetID()` 반환

#### (2) `session_game_manage.cs` / `session_ui.cs` — 영향 없음 ✅

두 파일 모두 `using static session_manage;`을 사용하지만, `session_manage`에는 static 멤버나 nested type이 없어서 실질적으로 아무것도 import하지 않습니다. `ActionType` enum은 `session_game_data.cs`에 별도 정의되어 있어 이번 변경과 무관합니다.

#### (3) 타이머 텍스트 vs 상태 메시지 경쟁 ⚠️ — 수정 필요

**가장 실질적인 문제.** `RandomMatchUI.Update()`는 `isMatching == true`인 동안 **매 프레임** `timerText`를 타이머 포맷(`"00:05"`)으로 덮어씁니다.

```
// RandomMatchUI.cs - Update()
timer += Time.deltaTime;
timerText.text = $"{minutes:00}:{seconds:00}";  ← 매 프레임 실행
```

`HandleStatusUpdate`도 같은 `timerText`에 상태 메시지를 씁니다.

```
// RandomMatchUI.cs - HandleStatusUpdate()
timerText.text = msg;  ← "Searching...", "Room Created: 1234" 등
```

**결과**: 상태 메시지가 한 프레임만 표시된 후 즉시 타이머 포맷으로 덮어씌워져 사용자에게 보이지 않습니다.

**참고**: 매칭 성공 후(`HandleMatchedAndReady`에서 `isMatching = false`)에는 `Update()` 타이머가 중지되므로, 카운트다운("3...", "2...", "1...")은 정상 표시됩니다.

#### (4) 이벤트 구독 `=` 대입 방식 — 잠재적 위험 💡

```
// RandomMatchUI.cs - StartRandomMatch()
matchManager.onStatusUpdate = HandleStatusUpdate;     // = 대입
matchManager.onMatchedAndReady = HandleMatchedAndReady; // = 대입
```

`+=` 대신 `=`를 사용하고 있어, 향후 다른 곳에서도 이 이벤트를 구독하면 기존 구독이 덮어씌워집니다. 현재 구독자가 하나뿐이므로 당장은 무해합니다.

#### (5) `CancelRandomMatch()` 이벤트 해제 순서 — 피드백 누락 💡

```
// RandomMatchUI.cs - CancelRandomMatch()
matchManager.onStatusUpdate = null;      // ← 먼저 해제
matchManager.onMatchedAndReady = null;   // ← 먼저 해제
matchManager.OnClickExitSession();       // ← 이후 호출: NotifyStatus("session exit") → UI에 미표시
```

이벤트를 먼저 해제한 후 `OnClickExitSession()`을 호출하므로, 세션 종료 성공/실패 메시지가 UI에 표시되지 않습니다.

#### (6) Firebase 초기화 중복 호출 — 기능상 안전 💡

`firebase_network.dbRef`가 `private static`이므로:

1. MainMenu → `session_manage.Start()` → `Initialize()` → `dbRef` 설정
2. TestServerConnect → `session_game_manage.Start()` → `Initialize()` → `dbRef` 재설정

`CheckAndFixDependenciesAsync()`는 다중 호출에 안전하지만, 불필요한 초기화가 중복 실행됩니다.

#### (7) Inspector 직렬화 값 유실 — 무해 ✅

`RandomMatchUI`에서 제거된 public 필드:
- `matchSuccessTime` (float, 기본값 3f → 씬에서 20으로 오버라이드되어 있었음)
- `nextSceneName` (string, 기본값 "TestGameScene")

Unity가 "Field was removed" 경고를 출력하지만, 이미 사용하지 않는 필드이므로 기능에 영향 없습니다.
